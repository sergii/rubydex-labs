# Lab 06 - X-Ray consequence benchmark, A/B/C

Date: 2026-09-13

GitHub Actions run: https://github.com/sergii/rubydex-labs/actions/runs/34762470255

Model: `gpt-5.6-luna`
Reasoning: `medium`
Samples: 3 per condition, each on a fresh GitHub-hosted VM

## Conditions

- A - source-only repository navigation
- B - source + Rubydex semantic-first navigation
- C - source + Rubydex + explicit architecture knowledge + targeted skill

The fixture models a proposed change from queued payment capture to a synchronous call. The deterministic scorer measures impacted flows/components, operational risks, verification scenarios, policy IDs, and deploy recommendation.

## What this run supports

For this small controlled fixture, forcing Rubydex semantic-first navigation did not improve median consequence correctness over source-only navigation. It increased median elapsed time by about 90% and median token usage by more than 4x.

Adding explicit architecture knowledge and a targeted skill changed the result materially: C reached exact consequence and knowledge scoring in every run, including 100% policy recall. This supports the broader X-Ray hypothesis that code structure alone is insufficient for company-specific consequence reasoning.

## What this run does not prove

C combines Rubydex and knowledge, so this experiment cannot attribute C's improvement specifically to the knowledge layer. A future condition D should test source + knowledge + skill without Rubydex.

Risk and verification recall were already 100% in A, creating a ceiling effect. The fixture is therefore too easy on those dimensions to measure whether semantic navigation helps with risk discovery.

The benchmark is intentionally small. Rubydex may become more valuable as repository size, lexical ambiguity, inheritance depth, indirect references, and cross-file noise increase. Lab 06 should therefore be followed by a larger or real-codebase X-Ray task before making a general claim about Rubydex efficiency.

## Immediate interpretation

The most important result is not "Rubydex loses." It is that, in this task, semantic code structure by itself was not the missing information. The missing information was architectural intent and policy. Rubydex is still useful as deterministic evidence, but the human-facing X-Ray value appears to emerge when evidence is combined with explicit knowledge and rules.
